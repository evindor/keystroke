# Keystroke 1.2.0

Released September 9, 2026.

This release adds Smart Match, a local semantic matcher served by a compiled
engine, fuzzy file search with the `~` prefix, `Ctrl+1`…`Ctrl+8` shortcuts and
animation tiers, and makes every keystroke cheaper on the shell's UI thread.

## New

- **Smart Match.** A small embedding model, running locally on the CPU,
  supplements exact and fuzzy search with action descriptions and semantic
  suggestions: it keeps launch, install and remove distinct, forgives small
  typos, and offers Chromium for "launch Chrome" when Chrome is absent. Spoken
  arithmetic such as "27 plus 90" becomes `27 + 90`; dictation and assistant
  prompts keep the original transcript. Results still need `↵` and keep their
  confirmations. Settings › Matching chooses **Off**, **Only voice** or **Voice
  and text** (the default) and the model, **Small (2M)** (the default) or
  **Large (8M)**. The first eligible query downloads the model (8 MB, pinned
  SHA-256 digests) and starts the runtime; ordinary search stays available
  meanwhile, and a failed setup leaves it that way with a **Retry Smart Match**
  row. The runtime unloads after two idle minutes. Details are in
  [matching/README.md](../../matching/README.md).
- **A compiled matching engine.** Smart Match is served by a 600 KB Rust binary
  with no machine-learning framework: ready in about 18 ms and resident at
  16 MiB, against roughly 250 ms and 92 MiB for the Python runtime. The plugin
  ships a static x86_64 build, so a fresh install needs only the model download.
  Another architecture builds the engine once with `cargo` from the included
  source; without a Rust toolchain, Python 3 with `uv` runs the equivalent
  pinned runtime. `huggingface_hub` is no longer used.
- **Learned query preferences.** Choosing a result teaches the palette to lift
  that result the next time the same query is typed or spoken in the same
  scope, so a preferred file can win over the file provider's discount. The
  preference decays with the same 14-day half-life as frecency and is stored
  in `usage.json` as hashed keys only, never as query text. Learning starts
  with selections made after this update.
- **Fuzzy file search and the `~` prefix.** Files and folders under `~` join the
  results from two characters on, and abbreviations work: `dwnlds` finds
  Downloads, `~dcmnts rpt` searches only files and folders for reports under
  Documents. `~` always selects file search and bypasses Smart Match.
  Settings › Files › **Search in the main palette** offers **Fuzzy** (the
  default), **Literal** or **Only with ~**; hidden entries are optional and
  gitignore rules stay respected. At most ten results mix into the main
  palette; `~` and the Files screen show up to sixty.
- **`Ctrl+1`…`Ctrl+8` run a result directly.** Holding `Ctrl` shows each of the
  first eight rows' digit in place of its icon. A disabled row is selected but
  not run, and the shortcut stays out of dictation and dmenu input modes.
- **Animation tiers.** Settings › Appearance gains **Animations**: **Off**,
  **Snappy** (the default) or **Fluid**, and **Window transition**: **Instant**
  (the default), **Fade** or **Slide up**. A menu level slides in from the side
  you came from, the selection is one highlight that glides between rows, the
  activated row flashes before the palette leaves, and the window fades or
  slides on an ease-out curve. All durations live in one table in
  `core/Motion.js`.

## Improvements

- **The UI thread stays idle while typing.** Profiled offscreen against the real
  providers, a keystroke cost 35 ms median and 287 ms worst case on the UI
  thread; it now costs 10 ms and 21 ms. Ranking keys are memoized, the search
  catalog is built once per summon and warmed before the first keystroke,
  refreshes from one provider re-run only that provider, and asynchronous
  refreshes respect the 25 ms typing debounce. `tools/profile_palette.py` is the
  harness.
- **Dictate to Clipboard** sits right after Convert Anything in the root menu.

## Fixes

- **File previews** sit below the path caption at their native size instead of
  covering it or being enlarged to fill the pane; a long path keeps its file
  name.
- **The selection highlight** follows the selection when typing removes the rows
  above it instead of vanishing or landing on the wrong row.

## Update

```sh
omarchy plugin update evindor.keystroke
```

If the shell still uses cached plugin code after updating, run
`omarchy restart shell`.

Requires Omarchy 4.0.2 or later. Smart Match needs network access once for the
model download; the shipped engine is a static x86_64 binary, and other
architectures build it with `cargo` or fall back to Python 3 with `uv`. Setting
Smart Match to **Off** keeps matching exactly as it was in 1.1.5.

Validation: 148 QML tests, 48 time-zone cases, the file, catalog, matching
worker, engine and session checks, the palette matching, shortcut, motion and
dictation checks, the application, voice, clipboard, Codex and hotkey checks,
plugin validation, site checks and qmllint passed offscreen. The extension
lifecycle check stops at its "update applied" step because of a timing race in
the check itself; it fails at the same step on the 1.1.5 tree, and every other
step of that check passes. See the [verification record](../verification.md).
