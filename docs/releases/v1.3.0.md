# Keystroke 1.3.0

Released September 10, 2026.

Extensions work again. Keystroke now loads community extensions itself instead
of asking omarchy-shell for them: the shell hands a third-party plugin a view of
the registry that contains only that plugin, and a service lookup that returns
only that plugin's own service, so an installed extension was never found. This
was the case on every Omarchy 4.0.x build, not only 4.0.3.

## Extensions

- **Keystroke hosts extensions.** `providers/Registry.qml` reads
  `~/.config/omarchy/plugins/*/manifest.json`, keeps the manifests that carry
  `"x-keystroke"` and whose folder name equals their id, and creates each
  `entryPoints.service` in its own object tree, injecting `shell`, `manifest`
  and `omarchyPath` as the shell would. The folder is scanned when the palette
  is created and on every open, so an extension installed by any route (the
  palette, `omarchy plugin add`, a copied folder) is picked up without a
  restart. A changed manifest recreates its service; a removed folder destroys
  it.
- **One switch.** Extensions no longer need, or get, an entry in `shell.json`:
  the palette installs with `omarchy plugin add --yes` (no `--enable`), and the
  **Loaded in omarchy-shell** row is gone. An installed extension is on unless
  you turn it off under Extensions → <name> or Settings → <name>; off keeps
  the service but sends it no queries.
- **Needs attention.** An extension whose `Service.qml` does not compile,
  exposes no `provider`, or declares another API version is listed with the
  reason on the Extensions screen and under Settings instead of vanishing.
- **Honest update status.** Quickshell 0.3.1 has no `Qt.clearComponentCache`
  (omarchy-shell guards the call), so the shell's rescan cannot drop cached
  QML. After **Update now** the status line says the new code loads on the next
  `omarchy-restart-shell`. A first install has nothing cached and loads at once.

## Fixes

- **Extension jobs finish in order.** A job was marked done the moment its
  `job.json` disappeared, before its `result.json` had been read, and the
  detached removal of a result could delete a newer job's result. A job now
  ends only when its result is finished, each result is finished once per
  palette instance, and the next job's wrapper drops the previous result. The
  check that follows an install or update no longer replaces the
  "Installed …" or "Updated …" status. This is the "update applied" race the
  1.2.0 and 1.2.1 records left open; `tests/extensions_check.py` passes end to
  end.

## After updating

```sh
omarchy plugin update evindor.keystroke
omarchy restart shell
```

The restart is needed for the palette's own new code, for the reason above.
Requires Omarchy 4.0.2 or later.

If you enabled an extension the old way, `omarchy plugin list` still shows it
as enabled and the shell runs a second, idle copy of its service next to the
one Keystroke hosts. `omarchy plugin disable <id>` removes the `shell.json`
entry and keeps the files; Keystroke keeps serving it.

The 1.2.1 note about extension services being unreachable after the 4.0.3
scoped-shell revocation no longer applies: Keystroke does not go through the
shell for them.

## For extension authors

Nothing changes in the manifest or in `Service.qml`. Keystroke, not Omarchy,
now creates the object; `shell` is Keystroke's own scoped shell handle.
[CONTRIBUTING.md](../../CONTRIBUTING.md) and
[docs/providers.md](../providers.md) describe the loading and the folder-name
rule.

Validation: 149 QML tests, 48 time-zone cases, the application, file, catalog,
matching worker, engine and session checks, the palette matching, shortcut,
motion, dictation and the new palette extensions check (a marked folder becomes
a provider with `shell`, `manifest` and `omarchyPath` injected; a broken and a
misnamed folder are reported; an unmarked bar widget is ignored), the full
extension lifecycle check through Omarchy's own scripts, the voice, clipboard,
Codex and hotkey checks, plugin validation, site checks and qmllint passed
offscreen. Verified live on Omarchy 4.0.3-1: the Timer extension from the
marketplace registers as a provider after a shell restart. See the
[verification record](../verification.md).
